## 1. 名詞

- **有密碼的 PDF**：檔案帶有加密設定（`PdfEncryptionQuery.IsEncrypted` 為真），分兩種：
  - **開啟密碼**：沒有密碼打不開（`PdfEncryptionQuery.NeedsOpenPassword` 為真）。
  - **使用限制**：開啟不用密碼，但限制了列印、複製等（`IsEncrypted` 為真、`NeedsOpenPassword` 為假）。這種檔案不需要使用者提供任何密碼就能解密。
- **解鎖**：把有密碼的 PDF 解密成沒有加密設定的暫存檔，再交給原本的動作處理。
- **略過**：使用者不提供這個檔案的密碼，只放棄這一個檔案，其他檔案照常處理。
- **停止**：放棄整個任務（現有的取消）。

## 2. 現況（2026-11-19 實測）

以 PdfSharp 產生的三種檔案（沒有密碼、只有使用限制、有開啟密碼）直接呼叫各 use case：

| 動作 | 事先給密碼（選項 `password`） | 執行中遇到要密碼 | 只有使用限制的檔案 |
| :--- | :--- | :--- | :--- |
| 解密 | 會先用（2026-11-19 修正前沒用到，卡片上的密碼等於白填） | 問密碼（`ExecuteWithPasswordRetryAsync`） | 不用密碼即可解密（同日修正：不再拿卡片上的密碼去試） |
| 分割 | 會先用 | 問密碼 | 直接處理，不問 |
| PDF → 圖片 | 會先用 | 問密碼 | 直接處理，不問（Windows 繪圖引擎是否接受，待 Windows 實測） |
| 壓縮、合併、翻譯、列印 | 不支援 | **規劃階段整批擋下**（`ValidateNotEncrypted`） | **一樣整批擋下** |

另外：

- 解密遇到**沒有密碼**的檔案也是整批擋下（「此檔案未加密，無須解除密碼」）。4.0 桌面端目前只把有密碼的檔案交給解密，3.x 與右鍵執行仍會整批失敗。
- 「同一批先用同一組密碼試」目前做在各介面（4.0 的 `_lastPassword`），不在 Core；3.x、CLI 各自有或沒有。
- 右鍵執行（CLI，沒有主視窗）沒有提供密碼的介面：`ConversionExecutionController` 預設回傳 `null`，等於「停止」，整個任務取消。
- 4.0 桌面端在 2026-11-19 起的過渡做法：有密碼的 PDF 時，目錄把壓縮、合併、翻譯、列印停用並說明「要先解密」。

### 2.1 問題

1. **一個檔案有密碼，整批都不做**：壓縮 10 個 PDF，其中 1 個有密碼，其他 9 個也不壓縮。
2. **要使用者自己繞路**：先「解密 PDF」產生無密碼的副本，再對副本做原本的動作，最後自己刪副本。
3. **只有使用限制的檔案也被擋**：這種檔案根本不用密碼，卻一樣被要求「先解除密碼」。
4. **「略過」等於「全部停止」**：`ExecuteWithPasswordRetryAsync` 收到 `null` 就拋出 `OperationCanceledException`，剩下的檔案都不處理。桌面端只能把按鈕寫成「停止」。
5. **右鍵執行遇到有密碼的檔案就整批取消**，也沒說哪個檔案需要密碼。
6. **錯誤訊息只說原因、不給辦法**：「此 PDF 檔案受密碼保護或已加密，請先使用「解除密碼」功能……」。

## 3. 目標

- 所有處理 PDF 的動作（壓縮、合併、翻譯、列印、分割、PDF → 圖片）遇到有密碼的檔案時，行為一致：
  - 只有使用限制：不問，直接解鎖後處理。
  - 有開啟密碼：先用這一批已輸入過的密碼試；打不開才問；輸入後解鎖並接著做原本的動作。
- 一批裡只有需要密碼的那個檔案等使用者，其他檔案照常處理。
- 使用者可以「略過這個檔案」：只放棄這一個，任務最後顯示「好 9 個，1 個略過」。
- 解密也照同一套：沒有密碼的檔案在解密時略過並註明「沒有密碼，不用解密」，不再整批失敗。
- 密碼只用在這一次，不寫進設定、歷史、日誌或任務紀錄；解鎖用的暫存檔用完立即刪除。
- 3.x（Fluent、Dashboard、CLI 進度視窗）、4.0 與右鍵執行共用同一套 Core 行為。

不在範圍內：

- 「加密 PDF」功能（之後另寫計畫）。
- 動作卡片上事先填密碼的欄位：除了解密卡片，其他動作一律在執行中、在該檔案的列上詢問，使用者不必事先知道哪個檔案有密碼。

## 4. 做法

### 4.1 共用的解鎖步驟（Core `Application`）

新增 `PdfUnlockStep`（名稱可再議），供所有處理 PDF 的動作在讀入每個來源檔前呼叫：

1. 不是 PDF，或 `IsEncrypted` 為假：直接回傳原路徑。
2. 只有使用限制（`NeedsOpenPassword` 為假）：不帶密碼解密到暫存檔，回傳暫存檔路徑。
3. 有開啟密碼：
   1. 先試這次任務的已知密碼（見 4.2），依輸入順序逐一試。
   2. 都打不開才呼叫 `RequestPasswordAsync`，`isRetry` 表示上一次輸入錯誤。
   3. 收到密碼：解密到暫存檔，成功後把這組密碼加入已知密碼；密碼錯誤則再問（`isRetry = true`）。
   4. 收到「略過」：回報這個檔案略過（4.3）。收到「停止」：取消任務。
4. 暫存檔放在 `StorageRuntime` 的 temp 目錄下的 `unlock/` 子資料夾，檔名用 GUID，副檔名 `.pdf`；不使用原檔名，以免在暫存區留下可辨識的名稱。
5. 回傳一個可 `Dispose` 的結果；動作處理完（成功、失敗、略過、取消）都在 `finally` 刪除暫存檔。
6. 程式啟動時清掉 `unlock/` 裡超過一天的殘留檔（當機或強制結束時留下的）。

輸出一律依**原始檔名**與原始位置產生，和沒有密碼時完全相同。

### 4.2 已知密碼放在 Core

- 新增 `ConversionPasswordCache`（只存在記憶體、只活在一次任務內），由逐檔處理的基底類別持有，取代各介面自己的「上一組密碼」。
- 暫停後在「歷史」按「繼續」：已知密碼不保留，遇到時重新詢問。
- 4.0 的 `_lastPassword`、Fluent 的對應邏輯在這一步之後移除，避免兩層都在重試。

### 4.3 三種回覆：密碼、略過、停止

- 新增 `PasswordPromptResult`：`Password(string)`、`Skip`、`Cancel`。
- `IConversionInteraction` 新增 `RequestPasswordResultAsync`；舊的 `RequestPasswordAsync`（`string?`）保留為相容包裝，`null` 視為 `Cancel`，讓 3.x 不必同時改。
- `ConversionExecutionCallbacks.PasswordPrompt` 同樣新增回傳 `PasswordPromptResult` 的版本；沒有提供時（右鍵執行、無介面）預設回 `Skip`，原因記為「需要密碼」。
- `PerFileConversionUseCaseBase` 收到 `Skip`：記錄該檔略過並繼續下一個檔案。
- `ConversionResult` 增加 `SkippedFiles`（每筆含路徑與原因：`NeedsPassword`、`NotEncrypted`）。全部檔案都被略過時，狀態為 `Failed`，錯誤寫「全部檔案都需要密碼，沒有處理任何檔案」。

### 4.4 各動作

| 動作 | 改法 |
| :--- | :--- |
| 壓縮 | 移除 `ValidateNotEncrypted`；逐檔先經 4.1 再壓縮 |
| 翻譯 | 同上 |
| 列印 | 同上；一批列印中略過的檔案不送印表機 |
| 合併 | 移除 `ValidateNotEncrypted`；讀入每個來源檔前經 4.1；略過的檔案從合併清單拿掉，其餘依原順序合併；剩不到 2 個檔案時不產生輸出，結果寫「只剩 1 個檔案，沒有合併」 |
| 分割、PDF → 圖片 | 改用 4.1（取代各自的 `ExecuteWithPasswordRetryAsync`），只有使用限制的檔案也確定可處理 |
| 解密 | 沒有加密設定的檔案記為略過（原因 `NotEncrypted`），不再整批擋下；卡片上的密碼視為第一組已知密碼 |

- 這幾個動作的 `Capabilities` 加上 `ConversionCapability.Password`。
- `ValidateNotEncrypted` 與對應的語系字串（`pdf_err_encrypted_*`）刪除；處理程式裡的 `PdfEncryptedException` 轉換保留，當作最後一道防線。

### 4.5 輸出檔沒有密碼

解鎖後處理的輸出檔不帶密碼，也不帶原本的使用限制。這是刻意的（使用者已經證明自己有密碼），但要說清楚：

- 密碼列的說明寫「輸出的檔案不會有密碼」。
- 結果列：來源有密碼的檔案，結果寫「完成（輸出沒有密碼）」。
- 之後有「加密 PDF」時，再考慮「輸出沿用原本的密碼」選項。

本節取代 [v4_desktop_ui_layout.md](v4_desktop_ui_layout.md) 待決事項「加密 PDF 經解鎖後再處理所產生的輸出檔是否仍帶密碼」，該條改為已決。

### 4.6 介面

**4.0 桌面端**

- 密碼列：「停止」改為「略過這個檔案」，並保留一個「全部停止」的次要按鈕；說明加「輸出的檔案不會有密碼」。
- 結果頁：略過的檔案列在最後，寫「已略過（需要密碼）」，旁邊放「再轉一次」（只帶這些檔案，回到同一個動作）。摘要寫「壓縮好 9 個，1 個略過」。
- 目錄：拿掉 2026-11-19 的過渡做法──壓縮、合併、翻譯、列印不再停用；上方說明改成只說「這個 PDF 要密碼才能開啟，處理時會在該檔案的列上問密碼」，不再列出「要先解密」的動作；只有使用限制時不顯示說明。「解密」仍依檔案顯示並排第一（使用者可能就是要拿掉密碼）。
- 移除 `_lastPassword` 與目錄裡 `NeedsUnprotectedInput` 的停用邏輯。

**右鍵執行（CLI 精簡視窗）**

- 不跳密碼輸入框（右鍵執行應該安靜完成）；需要密碼的檔案記為略過。
- 精簡視窗結果寫「好 9 個，1 個需要密碼」，按鈕「在 Clickra 中輸入密碼」：開啟主視窗，帶入這些檔案與同一個動作，並直接開始，讓檔案列問密碼。
- 安靜模式（不顯示視窗）：只記入歷史，原因「需要密碼」。

**3.x Fluent**

- 密碼對話框加「略過這個檔案」；文案經使用者確認後再改。

**語系**：新增「略過這個檔案」「全部停止」「已略過（需要密碼）」「沒有密碼，不用解密」「輸出的檔案不會有密碼」「在 Clickra 中輸入密碼」等字串，五種語言都補齊。

### 4.7 歷史紀錄

- 有略過的檔案時，任務仍記為成功，原因欄寫「1 個略過（需要密碼）」。
- 「再轉一次」帶回全部原始檔案；略過的檔案到時候再問密碼。
- 不記錄密碼，也不記錄「哪個密碼打開了哪個檔案」。

## 6. 測試

測試檔用 PdfSharp 在測試中產生（不放二進位檔進 repo），涵蓋：沒有密碼、只有使用限制、開啟密碼（RC4 128 與 AES-256 各一，AES-256 若 PdfSharp 無法產生則以 qpdf 產生並記錄在測試說明）。

**單元測試（Core）**

- 解鎖步驟：三種檔案各自的回傳；只有使用限制時不呼叫 `RequestPasswordAsync`；已知密碼命中時不問；密碼錯誤時 `isRetry` 為真；暫存檔在成功、失敗、略過、取消後都不存在。
- 壓縮、翻譯、列印、合併、分割、PDF → 圖片、解密：各一個「一批 3 個、中間一個有開啟密碼」的測試，分別回覆密碼、略過、停止。
- 同一批 2 個同密碼的檔案只問一次。
- 解密：混合沒有密碼的檔案時，沒有密碼的記為略過（`NotEncrypted`），其他成功。
- 合併：略過後剩 1 個檔案時不產生輸出。
- 無介面（`PasswordPrompt` 未提供）時記為略過，不取消任務。
- 結果、歷史、日誌、任務紀錄中搜尋不到測試密碼字串。

**架構測試**：見提交 9。

## 7. 驗收（Windows 實機）

- 壓縮 3 個 PDF（中間一個有開啟密碼）：前後兩個直接完成；中間那列要求密碼，輸入後完成；輸出檔名與沒有密碼時相同；結果寫「完成（輸出沒有密碼）」。
- 同一批 2 個用同一組密碼的檔案：只輸入一次。
- 密碼輸錯：同一列顯示「密碼不正確」，可重輸，其他檔案不中斷。
- 按「略過這個檔案」：其他照常完成，結果寫「壓縮好 2 個，1 個略過」，歷史註明略過；按「再轉一次」會再問密碼。
- 按「全部停止」：與現在的停止相同。
- 只有使用限制的 PDF：壓縮、合併、翻譯、列印、分割、PDF → 圖片都不問密碼直接完成。
- 合併時略過一個檔案：其餘照順序合併。
- 解密選了 3 個 PDF（1 個沒有密碼）：另外 2 個完成，沒有密碼的寫「沒有密碼，不用解密」。
- 右鍵壓縮含有密碼的一批：精簡視窗寫「好 2 個，1 個需要密碼」，按「在 Clickra 中輸入密碼」後主視窗問密碼並完成。
- 處理完後 `unlock/` 沒有殘留；強制結束後重開，超過一天的殘留被清掉。
- 設定、歷史、日誌中找不到密碼。
- 4.0 目錄：壓縮等卡片不再停用。
- 3.x 與 4.0 都通過；NativeAOT 發佈沒有新增裁剪警告。

## 8. 待決

1. 解鎖的暫存檔是否改成只在記憶體中處理（不落地）。各處理程式目前都吃檔案路徑，改成串流牽動太大，先用暫存檔加立即刪除；之後若有需要再評估。
2. 「全部停止」是否需要：多數情況「略過」就夠了。先保留，觀察使用情形。
3. 4.0 是否也提供「這次所有有密碼的檔案都略過」（一批很多加密檔時）。先不做。
