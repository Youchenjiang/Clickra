# 新介面接手右鍵執行

> 狀態：計畫（2026-11-28 起草）
> 對應：[v4_release_plan.md](v4_release_plan.md) 第 4 個 PR；[v4_desktop_ui_layout.md](v4_desktop_ui_layout.md) 4.5；畫布「Clickra 4.0 版面方案」的「右鍵執行」一列。
> 範圍：`Clickra.Desktop` 新增右鍵執行模式與精簡視窗；`ClickraLauncher`、`ClickraShell` 改成啟動它。完成後 3.x 右鍵進度視窗（`Clickra.CLI/Progress`）與套件裡的 `Clickra.exe` 才能移除（第 6 個 PR）。

## 1. 方向：沿用 3.x 的運作方式，換上新的畫面

**每按一次右鍵，啟動一個新介面的行程，只顯示一個精簡視窗；做完就結束。** 行程之間不直接溝通，只各自把狀態寫進 `tasks/`，主視窗的歷史頁讀這些檔案顯示「進行中」。這和 3.x 的 `Clickra.exe` 相同，換掉的只有畫面。

這取代 4.5 原本「主視窗已開就顯示在主視窗、多個右鍵工作排進同一個佇列」的決定（2026-11-15）。改回來的原因：

| | 一個工作一個行程（3.x、本計畫） | 單一行程加佇列（4.5 原決定） |
| :--- | :--- | :--- |
| 兩批檔案同時處理 | 可以，本來就會 | 不行，要另外做「依引擎同時跑」才恢復 |
| 一件工作當掉 | 只影響自己 | 正在跑和排隊中的全部中斷 |
| 使用者怎麼理解 | 按一次右鍵出現一個視窗，視窗就是那件工作 | 要理解佇列與「後面還有幾件」 |
| 要做的東西 | 精簡視窗、啟動參數 | 再加行程交接、佇列、主視窗被佔用時的處理 |
| 連續按右鍵 | 出現多個小視窗（錯開擺放） | 只有一個視窗 |
| 記憶體與啟動時間 | 每個工作各付一次 | 第二件起較省 |

4.5 當時要解決的「同一套進度畫面做了兩份」仍然解決：精簡視窗和主視窗的處理中、完成畫面用同一套元件與同一個 ViewModel，只是版面大小不同。

PowerPoint、LibreOffice 不能同時轉的問題由 `fix/office-engine-lock` 的跨行程 mutex 處理（第 2 個 PR），後來的工作在該檔案前等待。

## 2. 啟動

- 命令列沿用 3.x：`<動作> [--quiet] <檔案…>`，讓 `ClickraShell` 傳的參數與使用者既有的腳本不用改。`Clickra.Desktop.exe` 收到「第一個參數是已登錄的動作」時進入右鍵執行模式；其餘情況（沒有參數、參數都是檔案）照現在開主視窗。
- `ClickraLauncher`：有動作參數時也啟動 `Clickra.Desktop.exe`（現在是交給 `Clickra.exe`）。`ClickraShell` 不改。
- 右鍵執行模式**不建立主視窗**，也不載入轉檔、歷史、設定頁，只建立精簡視窗與它需要的 ViewModel。按「開啟完整視窗」時才建立主視窗。
- 精簡視窗用軟體繪圖（不啟動顯示卡繪圖），降低記憶體與啟動時間；換成完整視窗後維持同一種繪圖方式到行程結束。
- 啟動順序：先顯示視窗（檔名、0% 進度），再開始處理，不要等印表機、Office 偵測等初始化。

## 3. 依動作決定開哪一種視窗

| 動作 | 右鍵執行時 |
| :--- | :--- |
| 不用先選選項（壓縮、合併、PDF → 圖片、解密、翻譯、Office → PDF、圖片各項、轉換格式） | 精簡視窗，直接開始；選項用「功能預設值」 |
| 要先選選項（列印、分割、批次重新命名、Markdown → PDF／Word） | 直接開**完整視窗**到該動作頁，檔案已帶入，不自動開始 |

第二類在 3.x 是進度視窗裡各自的小畫面（`ProgressWindow.PrintOptions`、`VisualSplitter`、`BatchRename`、`MarkdownOptions`）；4.0 用動作頁取代，不另做小視窗。這個行程的完整視窗和一般主視窗相同，做完可以繼續處理別的檔案。

判斷依據放在 Core 的動作登錄（每個動作一個「右鍵執行前要先選選項」的旗標），介面不逐一寫死動作名稱。

## 4. 精簡視窗

約 440 × 200，不可調整大小，沒有分頁列；標題列是 16 的 Clickra 標誌、名稱與視窗按鈕。內容照畫布「右鍵執行」一列的五個狀態：

| 狀態 | 內容 | 自動關閉 |
| :--- | :--- | :--- |
| 處理中 | 功能圖示、目前檔名、整體進度條與百分比、「第 2 個，共 5 個」；右下「停止」，左下「開啟完整視窗」 | — |
| 全部成功 | ✓、摘要、存檔位置、「開啟所在資料夾」 | 5 秒後關閉，滑鼠移到視窗上就不關 |
| 需要密碼 | 鎖頭、檔名、密碼欄位、主要按鈕「解鎖並繼續」、次要「略過這個檔案」、說明「輸出的檔案不會有密碼」 | 不關 |
| 有檔案沒有成功 | ✕、「完成 2 個，1 個沒有成功」、檔名與一行原因、其餘檔案存在哪裡；左下「開啟完整視窗」、右下「開啟所在資料夾」 | 不關 |
| 沒有 Office 轉檔工具 | 黃色警示圖示、「還沒有能轉 Office 文件的工具」、還沒轉的檔案；右下「開啟 Clickra 準備轉檔工具」（換成完整視窗的該動作頁） | 不關 |

- 用詞照寫作指南：「取消」一律改「停止」（4.5 原文是統一用詞前寫的）。
- **需要密碼**：在精簡視窗直接輸入（4.5 原決定）；需要密碼的檔案不只一個時，同一組密碼先自動試（Core 已有），仍要再問就在同一個視窗接著問下一個。略過後結果寫「完成 4 個，1 個略過」。[pdf_password_unlock_plan.md](pdf_password_unlock_plan.md) 4.6「在 Clickra 中輸入密碼」那個按鈕不做，以本節為準。
- **開啟完整視窗**：同一個行程把精簡視窗換成主視窗版面的處理中或完成畫面，工作不重新開始。
- **處理中關閉視窗**：和主視窗相同（在背景繼續／停止，系統匣圖示）。
- **多個精簡視窗**：新視窗相對前一個往右下錯開 28 px，超出螢幕時回到起點。位置由 `tasks/` 裡正在執行的工作數決定，不需要行程互相溝通。
- **不搶焦點**：精簡視窗出現時不取得鍵盤焦點（使用者可能正在檔案總管繼續操作）；需要密碼時才閃工作列提醒。

## 5. 安靜模式

設定「從右鍵選單執行時不顯示視窗」開啟，或命令列帶 `--quiet` 時：

- 第一類動作不顯示視窗，完成或失敗時發系統通知（若有開啟「處理完成時通知我」）。
- 需要密碼：記為略過，通知寫「1 個檔案需要密碼」；點通知開啟完整視窗到同一個動作、帶入那些檔案（通知出現時處理的行程多半已結束，所以是新開，不是接回原行程）。
- 第二類動作（要先選選項）仍然開完整視窗；安靜模式沒辦法替使用者選列印選項。
- 安靜模式下不建立任何視窗物件。

## 6. 和主視窗的關係

- 主視窗開著時按右鍵：照樣是獨立的精簡視窗，不動主視窗（使用者可能正在選檔案或選動作）。
- 主視窗歷史頁的「進行中」列出其他行程的工作（讀 `tasks/`，已有）；確認它對別的行程的工作只顯示進度與「停止」，停止透過任務檔的取消旗標（沿用 3.x 的做法，若尚未實作則本 PR 補上）。
- 主視窗自己的排隊、插隊留在 4.1。

## 7. 先量，再定案

本計畫的兩個風險是記憶體與啟動時間。**實作的第一個 commit 只做最小的右鍵執行模式（啟動參數、空的精簡視窗、軟體繪圖），量完回報再繼續**：

| 量什麼 | 怎麼量 | 可以接受 |
| :--- | :--- | :--- |
| 右鍵到視窗出現 | 各 5 次取中位數，和 3.22 的 `Clickra.exe` 比 | 0.5 秒以下，或不超過 3.x 的兩倍 |
| 精簡視窗行程的記憶體 | 工作管理員的私人工作集，閒置時與壓縮一個 10 MB PDF 時 | 閒置 60 MB 以下 |
| 同時開 3 個 | 總記憶體、有沒有互相卡住 | 180 MB 以下 |

超過時先試：延後字型載入、只載入一種字重、關掉用不到的 Avalonia 功能。仍然差很多就停下來回報，由使用者決定要接受、改成單一行程，或讓精簡視窗用更輕的方式做。

## 9. 驗收（併入 4.0 驗收）

- 主視窗沒開時右鍵壓縮 3 個 PDF：只出現精簡視窗，做完 5 秒後關閉。
- 連續對三批檔案按右鍵：三個視窗錯開、同時進行、互不影響；其中一批是 PPT、另一批也是 PPT 時，後一批顯示等待，兩批都成功。
- 主視窗開著、正在選動作時按右鍵：主視窗不變，歷史頁「進行中」看得到那件工作。
- 中間一個檔案有密碼：在精簡視窗輸入後完成；按略過則摘要寫略過。
- 讓一個檔案失敗：視窗不關，寫出檔名與原因。
- 沒有 Office 也沒有 LibreOffice 時右鍵轉 Word：顯示第五種狀態，按鈕開完整視窗。
- 右鍵列印、分割、批次重新命名、Markdown → PDF：直接開完整視窗到動作頁，檔案已帶入。
- 安靜模式：沒有視窗，有通知；有密碼的檔案通知寫明，點了開完整視窗。
- 處理中按「開啟完整視窗」：進度不中斷。
- 用工作管理員結束一個精簡視窗的行程：其他工作照常；重開主視窗，歷史頁顯示那件「沒有做完就中斷了」。
- 第 7 節三項量測各再量一次。

## 10. 待決

1. 多個精簡視窗是否要合併成一個視窗多列進度（像 Windows 的複製對話框）：4.1 看使用情形再決定。
2. 精簡視窗在高 DPI 與多螢幕的擺放位置：先放在滑鼠所在螢幕的右下角工作區內，驗收時看是否擋到東西。
