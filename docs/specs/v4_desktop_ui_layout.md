## 1. 設計原則

1. **一個畫面只問一件事**：每個狀態只有一個主要問題與一顆主要按鈕。
2. **同一個視窗，不換頁**：放入檔案前後是同一個畫面的兩種狀態，以收合／展開動畫銜接；檔案清單、歷史詳情都在原地展開。
3. **檔案優先**：先放檔案，再只列出這些檔案能用的動作。不提供「先選工具再選檔案」的入口（此需求由檔案總管右鍵選單承擔）。
4. **白話文字**：用「讓檔案變小」而不是「最佳化內容串流」；進階項目收在「進階選項」。
5. **視窗永遠不出現整頁捲動條**：每一頁最多只有一個捲動區，工具列與主要按鈕固定不動。

## 2. 視窗規格

| 項目 | 數值 | 原因 |
| :--- | :--- | :--- |
| 預設大小 | **最多 960 × 660**，第一次開啟時不超過螢幕可用寬度的 70%、高度的 80% | 見下方說明 |
| 最小大小 | **760 × 520** | 寬 760 時動作目錄仍可一列排 4 張卡片；高度 600 以上時「已放入檔案」狀態的全部內容（含開始按鈕）不需捲動，低於 600 時依第 5 節由區塊內部捲動 |
| 內容欄最大寬度 | **860**，水平置中 | 視窗最大化時內容不會被拉得過寬，閱讀行長維持穩定 |
| 啟動位置 | 螢幕置中；之後記住上次的大小與位置 | 延續 3.x 行為 |
| 可否調整大小 | 可；可最大化 | — |
| 視窗外框圓角 | **跟隨作業系統，程式不自己畫** | Windows 11 與 macOS 由系統自動加圓角；Windows 10 為直角；Linux 依桌面環境而定。自己畫圓角需要關掉系統外框，會失去系統陰影、貼齊與縮放行為 |

**為什麼依螢幕縮小：** 在 1920 × 1080 加 150% 縮放（等效 1280 × 720）的筆電上，960 × 660 幾乎佔滿整個螢幕高度，實際使用時感覺過大（2026-11-15 在 Windows 實機確認）。因此第一次開啟時取「960 × 660」與「可用寬度 70%、高度 80%」中較小的值，在這種螢幕上約為 896 × 537；大螢幕仍是 960 × 660。之後記住使用者調整過的大小。

**上限高度為什麼是 660：** 最常見的筆電環境有兩種：1366 × 768（縮放 100%）與 1920 × 1080（縮放 150%，等效 1280 × 720）。扣掉工作列與視窗標題後，後者可用高度約 670。660 是能在這兩種環境完整顯示、不被工作列切到的最大整數值。

**預設寬度為什麼是 960：** 內容欄 860 加上左右留白後約 910，960 剛好容納；同時在 1280 寬的等效螢幕上，旁邊還留得下一個檔案總管視窗，方便把檔案拖進來。

現有 `MainWindow.axaml` 的 `960 × 680 / 720 × 520` 應改為上表數值。

## 3. 視窗結構

```text
┌──────────────────────────────────────────────────────────┐
│ [圖示] Clickra    轉檔  歷史  設定              ─  □  ✕ │  工具列 48
├──────────────────────────────────────────────────────────┤
│                                                          │
│            內容欄（最大寬 860，置中）                    │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

- **導覽**：只有三個分頁「轉檔／歷史／設定」，放在頂部工具列，目前分頁以底線標示。不使用側欄（只有三個目的地，整條側欄大多是空的），也不使用底部狀態列。
- **左上角圖示**：使用 `assets/primary/clickra-icon-primary-*.png`（正式圖示），不另外繪製。
- **「關於」**：併入設定頁最下方，不是獨立分頁。
- **引擎狀態**：平常不顯示。只有出問題時才提示：在轉檔頁以一條警示列說明（例如「找不到可用的 Office 轉檔工具」並附「前往設定」），以及在設定頁對應項目顯示。

### 3.1 工具列與系統標題列的關係

| 平台 | 行為 |
| :--- | :--- |
| Windows 10/11 | 工具列延伸進標題列（`ExtendClientAreaToDecorationsHint`），整個視窗只有一條上欄；右側保留系統視窗按鈕的位置 |
| macOS | 同上；左側保留紅綠燈按鈕的位置，圖示與名稱往右讓 |
| Linux | **待驗證**。若所用的 Avalonia 版本無法延伸，工具列會顯示在系統標題列下方，此時隱藏工具列上的圖示與「Clickra」字樣，只留三個分頁，避免名稱出現兩次 |

執行時以 `IsExtendedIntoWindowDecorations` 判斷是否真的延伸成功，再決定是否顯示圖示與名稱。

## 4. 各頁版型

### 4.1 轉檔（主畫面）

由上下兩個區塊組成：**檔案區**（上）與**動作區**（下，底色較暗）。

| 狀態 | 檔案區 | 動作區 |
| :--- | :--- | :--- |
| A. 還沒放檔案 | 高約 356 的拖放區：圖示、「要處理什麼檔案？」、一句說明、「選擇檔案」按鈕 | 「最近處理」最多 3 筆，右上有「全部歷史」連結 |
| B. 已放入檔案 | 收成高 72 的窄列：檔案類型圖示、「3 個 PDF 檔案」、檔名摘要、「管理檔案」、「重新選」 | 先顯示**動作目錄**：標題「要對這些檔案做什麼？」→ 動作卡片（一列 4 張）。點卡片後整個動作區換成該動作的**動作頁**：「‹ 所有動作」＋動作圖示＋說明句 → 設定卡或工作區 → 最下方「存到哪裡」與「開始」按鈕 |
| C. 管理檔案 | 窄列原地往下展開成清單（浮在動作區上方、有陰影）：每列有順序、檔名、頁數與大小、移除；最下方可再加入檔案；按鈕變為「完成」 | 變淡且暫時不能操作，位置與高度不變 |
| D. 拖曳檔案經過視窗 | 工具列以下整片蓋上半透明遮罩與強調色虛線框，中央寫「放開以加入 N 個檔案」；拖曳的檔案中有 Clickra 不能處理的，另起一行「另外 N 個 Clickra 不能處理，放開後會略過」。還沒放檔案時字樣為「放開以開始」 | — |
| E. 處理中 | 維持窄列，但不能再管理或重選檔案 | 標題「正在壓縮第 2 個，共 3 個」與整體百分比 → 整體進度條 → 每個檔案一列（完成／處理中／等待中）→ 最下方存檔位置與「取消」（有框、非強調色） |
| F. 完成／失敗 | 維持窄列 | 標題為結果摘要（例如「壓縮好 2 個，1 個沒有成功」）→ 每個檔案一列，成功顯示結果（如大小變化），需要補救的顯示補救欄位（如密碼），失敗顯示一行白話原因與「再試一次」→ 最下方左側「處理其他檔案」，右側主要按鈕「開啟所在資料夾」 |

- **A → B 的動畫**：檔案區高度由 356 收到 72（約 0.5 秒、先快後慢），同時動作區內容淡出，動作卡片再依序由下往上淡入。「重新選」反向播放。
- **一律分兩層（目錄 → 動作頁）**：每個動作都有自己的動作頁，不論它只有一項選項還是需要完整工作區，進出方式都一樣。這樣將來加入「加上密碼」這類動作時，只要多一張卡片，不必改版面。
- **目錄與動作頁之間的動畫**：點卡片時，動作頁從右側滑入（約 0.36 秒），動作圖示稍微放大彈出；按「‹ 所有動作」時目錄從左側滑回，卡片依序淡入。上方檔案窄列始終固定不動。系統設定「減少動態效果」時改為直接切換。
- **動作目錄**：每張卡片只有「圖示 → 短名稱」，**置中排列**：圖示 52 放在 68 × 68 的淺色圓角底（深色主題 `#E6EAF0`，淺色主題白底加細框）上，名稱 20 粗體；不放說明句、不放 › 箭頭，整張卡片可點，滑過或用鍵盤選到時才以提示顯示一行說明。一列 **4 張等寬**，最多兩列共 8 張剛好填滿動作區；超過 8 個時增加第三列，只有卡片區在內部捲動。只列出目前檔案類型可用的動作，**一律從左上開始排**；「重新命名」每種類型都有，**永遠排在最後一張**。動作少時卡片不拉寬、不置中，右側與下方留空。**只有一兩個動作時也照樣先顯示目錄**，不自動跳進動作頁，讓使用者每次看到的流程都一樣。圖示使用 `assets/features/*.svg` 的正式功能圖示；圖示與排列順序和檔案總管右鍵選單一致。
- **標題**：目錄的標題是問句「要對這些檔案做什麼？」；動作頁的標題是「‹ 所有動作」連結、動作圖示（32）與該動作的**功能名稱**（見 4.10），三者同一行。
- **動作說明的格式**：說明句只出現在卡片的滑過提示裡，所有動作統一為「把＋對象＋動作＋結果」一句話，12 字上下；不寫好處、不加第二句補充、結尾不加句號。意思相近的動作要靠**卡片名稱本身**分得出來（例如圖片的「分別轉成 PDF／合成一份 PDF／拼成長圖」），不能靠提示。目標還沒選定時用「其他」，不用「另一種」（例如「把圖片轉成其他格式」）。

  全部動作的短名稱、說明句與功能名稱見 4.10。

- **開始按鈕只出現在動作頁**：目錄上沒有「開始」，因為還沒決定動作。動作頁的主要按鈕寫「開始＋動作」（例如「開始壓縮」「開始解密」）；必選選項還沒選時呈停用並寫出要先選什麼。
- **存檔位置**：動作頁左下角一行顯示這次會存到哪裡，依設定頁「轉好的檔案存到」顯示「存到原本的資料夾／存到桌面／存到下載／存到 D:\輸出」（自訂路徑過長時中間以「…」省略，滑過顯示完整路徑）。旁邊的「變更」**只改這一次**，不改設定；改了之後文字變成「這次存到 …」，資料夾圖示改用強調色，並多一個「還原」。要永久改到設定頁。批次重新命名直接改原檔名、不產生新檔，所以沒有這一行。
- **沒有選項的動作**（例如 Office 轉 PDF）：動作頁仍然存在，在設定卡的位置以一行小字說明「這個動作沒有需要調整的選項。用 Microsoft Office 轉檔　變更」。
- **順序會影響結果的動作**（PDF 合併、圖片合併、拼接長圖）：屬於需要完整工作區的動作，見 4.6。
- **設定卡**：不重複動作名稱與說明，只顯示該動作最重要的一項設定及其名稱（例如「壓縮程度」三選一），其餘收在「進階選項」。
- **必選選項**：有些動作一定要先決定一件事才能執行，例如「轉換格式」要選目標格式、「翻譯」要選語言、「列印」要選印表機。這類選項就是設定卡上的那一項主要設定；有預設值可用時（功能預設值、系統預設印表機）先帶入，沒有時「開始」按鈕維持停用並提示要選什麼。因此圖片的五種格式轉換在介面上是**一個**動作「轉換格式」，不是五個。
- **能當場補救的問題不算失敗**：處理到一半才發現缺少某樣東西時，不直接判定失敗，而是在那個檔案的列上當場要求補上，補完自動接著做原本的動作。第一個適用情況是 **PDF 有密碼**：其他檔案照常處理，這個檔案標示「需要密碼」（鎖頭圖示，不用失敗的紅色叉號），列上直接出現密碼欄位與「解鎖並壓縮」按鈕；程式在內部先解除密碼再執行原動作，使用者不必自己先去跑一次「解密 PDF」。密碼錯誤時在同一列提示「密碼不正確」並可重輸；密碼只用於這一次，不儲存。同一批有多個加密檔時，輸入的密碼先套用到其餘同樣需要密碼的檔案，仍打不開的才個別再問。
- **真正的失敗**（檔案損毀、沒有寫入權限等）才顯示紅色叉號、一行白話原因與「再試一次」。
- **混合類型的檔案**：目錄只列出所有檔案都能用的動作；若只剩「重新命名」，卡片上方加一張說明卡並提供一鍵篩選（見 4.8）。

各狀態與各檔案類型的畫面見設計畫布。

### 4.2 歷史

- 上方固定一列：標題「歷史」、篩選（全部／成功／失敗，附筆數）、「清除歷史」。
- 進行中的工作固定在篩選列下方並顯示進度，**不隨清單捲動**；沒有進行中的工作時這一塊不佔位置。同時有多個時最多顯示 2 個，其餘收成一行「還有 N 個進行中」。
- 其下為清單（單欄）：每筆已完成的紀錄一列，顯示成功或失敗圖示、檔名、動作、時間。
- **點一列在原地展開詳情**（來源、輸出或失敗原因、時間與耗時），並提供「開啟檔案／再試一次」與「開啟所在資料夾」。同時間只展開一筆。
- 沒有紀錄時，清單位置顯示一句「還沒有處理過檔案」與「去轉檔」按鈕。

### 4.3 設定

設定分成兩類，以頁面右上角的切換鈕「一般／功能預設值」分開，兩類不混在同一個清單裡：

| 分頁 | 內容 | 性質 |
| :--- | :--- | :--- |
| **一般** | 一般（存檔位置、介面語言、外觀）、行為（從右鍵選單執行時不顯示視窗、處理完成時通知我、暫存工作保留）、檔案總管右鍵選單（要顯示的功能）、關於（一列：左邊版本與「所有處理都在這台電腦上完成」，右邊三個同大小的圖示按鈕：程式碼圖示＝GitHub 專案頁、日誌圖示＝檢視日誌、信封圖示＝寄送問題回報；後兩者沿用 3.x 的問題回報功能） | 影響整個程式，與做哪個動作無關 |
| **功能預設值** | 依檔案類型分組：PDF（壓縮程度與其選項、翻譯語言、轉圖片格式，選項與 4.9 一致）、Office 文件（轉檔工具、LibreOffice 安裝狀態）、Markdown（文件範本、紙張大小），之後的模組照此新增一組 | 各功能自己的預設選項 |

- **功能預設值的用途**：從右鍵選單執行，或在轉檔頁沒有另外調整時，使用這裡的設定。分頁最上方以一句話說明這一點。
- **與轉檔頁設定卡的關係**：設定卡的初始值取自功能預設值；在轉檔頁臨時改的選項只影響那一次，不會寫回預設值（延續 3.x「單次轉換選項不改全域設定」的行為）。
- **不自動記住上次的選項**：若自動記住，在視窗裡臨時選一次「最小檔案」就會悄悄改變之後右鍵選單（尤其安靜模式）的結果。改為明確操作：設定卡上的值和預設值不同時，旁邊出現「設為預設值」連結，按了才寫回功能預設值。
- **版型**：兩個分頁都放在**同一個**區塊裡（區塊固定、內部捲動），分**三欄**：左欄是群組名稱（寬 170、17 粗體，只寫在該組第一列；「功能預設值」的群組就是功能名稱，例如「壓縮 PDF」，Markdown 那組寫「Markdown」），中欄是設定名稱（16），右欄是控制項（下拉選單 16、最小寬 170；分段滑桿寬 280、刻度名稱 13）。每列高 62。組與組之間用較明顯的分隔線，同一組的列之間用淡分隔線。
- 設定變更立即生效，不需要「儲存」按鈕。
- **文字規則**：
  - 設定名稱本身要說得清楚，不靠下方的說明文字。例如用「從右鍵選單執行時不顯示視窗」而不是「安靜模式」加一行解釋。
  - 說明文字只在名稱無法表達「目前狀態」或「後果」時才加（例如右鍵選單的顯示項數），且不超過一行。
  - 不使用「填 0 代表永久」這類特殊數值；特殊情況做成獨立的開關。例如「暫存工作保留」為天數欄位加一個「永久」開關，開啟時隱藏天數欄位。

### 4.4 檔案總管右鍵選單

- **視窗內不提供「隱藏功能」的設定**：視窗已依檔案類型只列出可用動作，不需要再讓使用者關閉。
- **右鍵選單可以選擇要顯示哪些功能**：設定頁「一般」分頁的「檔案總管右鍵選單」一組只有一列（Windows 11 設定常見的「開關加展開箭頭」樣式）：左邊是名稱與摘要，右邊依序是總開關與展開箭頭；點箭頭在原地展開清單。總開關關閉時箭頭隱藏、摘要顯示「已關閉」。清單依檔案類型分列（文件／PDF／圖片／整理），每列左邊是分類名稱，右邊每個功能是一個**標籤**（可換行）：顯示中＝淡強調色底、強調色框、前面打勾；隱藏＝灰框、灰字、前面加號。顯示與隱藏靠勾和加號的**形狀**分辨，不只靠顏色。點標籤切換，立即生效；清單上不放「點一下切換」之類的說明文字。
- **從最小的版本做起**：只有開與關；不做排序、不做依副檔名個別設定。
- **總開關**：「在右鍵選單顯示 Clickra」。開關旁只放箭頭圖示，不放文字按鈕。關閉後整個 Clickra 選單不出現，但各功能的勾選狀態會保留，重新打開就恢復原樣。總開關取代「全部取消」按鈕。
- **分類全勾／全消**：不另外加按鈕，分類名稱本身就是一個勾選框（不另外顯示數量）。該分類全部顯示時它是勾選狀態，點一下全部隱藏；部分顯示時是「部分」狀態，點一下全部顯示；全部隱藏時點一下全部顯示。
- **不放「恢復全部顯示」**：每個分類名稱就能一次全勾，總開關負責全部關閉，不需要另一個按鈕。
- **讓使用者知道目前狀態**：這一列的摘要文字隨時反映現況：「18 項全部顯示（預設）」、「顯示 15 項，已隱藏 3 項」或「已關閉」。勾選後立即生效，沒有儲存步驟，所以用箭頭展開與收合、不使用「完成」按鈕；只是打開看看、沒有改動時，摘要維持原樣。
- **只在有右鍵整合的平台顯示這一組**：目前只有 Windows 有實作（`src/ClickraShell`）。macOS Finder 快速動作與 Linux 桌面動作屬於 4.0 第三階段規劃、尚未實作；在這些平台上先隱藏這一組，等整合完成後再顯示，並把標題改成該平台的說法（例如「Finder 快速動作」）。
- **預設全部顯示**：升級後選單不會無故變少；選單本來就依檔案類型過濾。在選單中關掉的功能，在視窗裡仍然可以使用。
- **圖片格式轉換收成子選單**：右鍵選單中 PNG／JPG／WebP／GIF／HEIC 五項合併為「轉換格式 ▸」一個子選單，與視窗內「轉換格式」是一個動作、目標格式為必選選項的做法一致。勾選清單中也只算一項。

### 4.5 從右鍵選單執行時的視窗

4.0 **沒有另外設計的「轉換中視窗」**。處理中與完成的畫面只有一套（4.1 的狀態 E、F），依啟動方式用不同大小呈現：

| 啟動方式 | 呈現 |
| :--- | :--- |
| 在主視窗按「開始」 | 同一個視窗直接進入狀態 E，完成後進入狀態 F，不開新視窗 |
| 從右鍵選單執行，主視窗沒開 | 跳出**精簡視窗（約 440 × 200）**：只顯示目前檔案、整體進度條與百分比、「第幾個，共幾個」、「取消」，以及「開啟完整視窗」連結。完成後同一個小視窗顯示結果：**全部成功**時只有摘要、存檔位置與「開啟所在資料夾」，5 秒後自動關閉；**有檔案需要密碼**時小視窗直接顯示檔名、密碼欄位與主要按鈕「解鎖並壓縮」，「開啟所在資料夾」降為連結，不自動關閉；**有真正的失敗**時直接寫出檔名與一行白話原因，主要按鈕仍是「開啟所在資料夾」，不自動關閉。需要處理的檔案超過一個時只列第一個，後面加「還有 N 個」連結，點了才換成主視窗的狀態 F |
| 從右鍵選單執行，主視窗已開 | 不跳小視窗；工作出現在主視窗（正在轉檔頁時顯示狀態 E，否則顯示在歷史頁固定的「進行中」區塊） |
| 從右鍵選單執行，且開啟「從右鍵選單執行時不顯示視窗」 | 不顯示視窗，只在完成或失敗時發系統通知。有檔案需要密碼時通知寫明「1 個檔案需要密碼」，點通知才開啟精簡視窗輸入 |

- 精簡視窗沒有分頁列，只有圖示、名稱與視窗按鈕；不可調整大小。
- 「開啟完整視窗」會把精簡視窗換成主視窗的狀態 E（同一個工作，不重新開始）。
- 同時執行多個右鍵工作時不各開一個小視窗：排入同一個佇列，小視窗顯示目前這一個並註明後面還有幾個。
- 3.x 的獨立進度視窗（`ProgressWindow`、`TaskProgressPage`）由本節取代。系統匣圖示是否保留**尚未決定**。

### 4.6 需要完整工作區的動作

**PDF 分割**、**批次重新命名**，以及**順序會影響結果的動作**（PDF 合併、圖片轉成 PDF、圖片合併、拼接長圖）需要預覽或排序，塞不進一張設定卡。這些動作的動作頁不放設定卡，直接放完整工作區：

- 標題列與其他動作頁相同：「‹ 所有動作」回到目錄，旁邊是動作圖示與說明句。
- 上方檔案窄列、最下方存檔位置與主要按鈕的位置不變，與其他動作一致。
- **在 960 × 660 內不得出現整頁捲動**：工作區裡只有一個區域會隨內容長短伸縮並在內部捲動（分割的頁面縮圖區、重新命名的預覽清單、合併的順序清單），其餘部分固定。

**PDF 分割**

- 上方三選一：自訂切點／每一頁一份／每 N 頁一份（選 N 時旁邊出現頁數欄位），右側一行提示操作方式。份數顯示在主要按鈕上。
- 頁面縮圖依序換行排列，兩頁之間的縫隙可點擊加上或取消切點（只在自訂切點模式可點）；每頁下方一條色帶標示屬於第幾份，兩種顏色交替。
- 主要按鈕「開始分割成 N 份」。
- 一次只分割一個檔案；放入多個 PDF 時，分割只套用「每一頁一份」或「每 N 頁一份」，自訂切點不可用。

**批次重新命名**

- 左欄是規則：取代文字（尋找／改成）、加上編號（起始編號、位置；位數由起始編號的寫法決定，例如寫 01 就是兩位數）、加上日期、加上前後文字，以勾選框開關，打勾才展開欄位。大小寫、副檔名、正規表示式收在「進階選項」。
- 右欄是預覽清單：每列「原檔名 → 新檔名」，標題列右側顯示「N 個都會改名」。新名稱重複或含有不允許的字元時，該列標示並寫原因，主要按鈕停用。
- 最下方左側固定提示「會直接改掉原本的檔名」，主要按鈕「重新命名 N 個檔案」。
- 只放入資料夾時，目錄只有「重新命名」一張卡片。

**合併與拼接**

- 工作區主體是順序清單：每列有拖曳把手、順序、檔名、頁數，以及往前／往後按鈕；上方附「依檔名排序／依修改時間／反過來」。
- 清單下方是「合併後的檔名」欄位。主要按鈕「開始合併」。

### 4.7 第一次使用與空白狀態

- **第一次開啟**：轉檔頁下方區塊沒有「最近處理」可列時，改放一則提示：右鍵選單的示意圖、「也可以在檔案總管直接使用」、一行說明，以及連到設定的「選擇右鍵選單要顯示的功能」。有任何紀錄後就換回「最近處理」。
- **歷史沒有紀錄**：不顯示篩選與「清除歷史」；清單區塊中央是圖示、「還沒有處理過檔案」與「去轉檔」按鈕。
- **沒有 Office 轉檔工具**：放入 Office 文件時動作照常顯示並選中，但設定卡換成提示「這台電腦還沒有能轉 Office 文件的工具」與一行說明，按鈕「下載 LibreOffice」（此時它是畫面上唯一的強調色按鈕）及連結「已經裝好了？指定位置」。主要按鈕停用並顯示「先準備轉檔工具」。下載中同一張卡片顯示進度、「下載完成後會自動開始轉檔」與「取消下載」，主要按鈕改為「下載完成後開始」。

### 4.8 其他狀態

- **混合類型、沒有共同動作**：目錄只剩「重新命名」一張卡片；卡片上方的說明卡寫「PDF 和圖片能做的事不一樣」，並提供「只留下 3 個 PDF」「只留下 2 張圖片」這類一鍵篩選按鈕（依實際類型與數量產生）。
- **真正的失敗**：每一列寫白話原因，旁邊只放對這個原因有用的按鈕：檔案損毀→「在資料夾中顯示」；工具沒有回應或暫時性錯誤→「再試一次」。不提供沒有用的「再試一次」。
- **輸出檔已存在**：屬於「能當場補救」的情況。處理照常繼續，該列暫停並寫「資料夾裡已經有「…」」，提供「保留兩個」（排第一，是安全的預設）、「取代舊檔」、「略過」，以及「之後遇到也這樣處理」勾選框。標題改為「正在壓縮，有 1 個需要你決定」。
- **確認對話框**：只用在會遺失進度或資料的操作，按鈕寫動作本身、不寫「確定／取消」，安全的選項是強調色並為預設焦點：
  - 處理中按「取消」或關閉視窗：「要停止處理嗎？」／「已經完成的 1 個會保留，剩下的 2 個不會處理」，按鈕「停止」「繼續處理」。
  - 清除歷史：「要清除所有歷史嗎？」／「只會清除紀錄，轉好的檔案不會被刪除」，按鈕「清除」「保留」。

### 4.9 選項卡片

**共通規則**

- **一律靠左、由上往下排**：標籤單獨一行在上，控制項在下並撐滿卡片寬度；補充說明、警示放在控制項下方。卡片裡不把任何東西推到右邊，也不用「標籤在左、控制項在右」的左右對齊排法。「進階選項」「設為預設值」這類連結放在卡片最下方，由左往右排。
- 轉檔畫面中唯一靠右的元素是檔案窄列的「管理檔案／重新選」與最下方的主要按鈕；工作區的小標題列（例如「合併順序」）也照靠左排，按鈕緊接在標題之後。
- 設定頁是設定清單，不是選項卡片，維持「名稱在左、控制項在右」的清單排法（4.3）。
- 只露一項主要選項，其餘收在「進階選項」，點了在同一張卡片裡展開；展開後太高時只有動作區中段在內部捲動。
- **控制項依選項的性質選**：
  - **有大小、程度之分**（PDF 壓縮三段、圖片壓縮四段）→ **分段滑桿**：只能停在刻度上（拖動時吸附，方向鍵一次一段），每個刻度下方寫名稱，目前那段加粗；滑桿上方顯示目前這段的名稱與一句說明（例如「平衡　適合一般分享」）。只有兩個選項時不用滑桿。
  - **風格不同、要看才知道差在哪**（文件範本）→ **預覽卡片**：一列並排，每張是一頁縮圖加名稱，選中的以強調色外框標示；最後一張是「選擇 Word 範本」（虛線框），選好後換成該範本的縮圖與檔名。
  - **少數幾個、彼此平等、沒有順序**（目標格式、雙面、方向）→ 分段按鈕。
  - **一長串項目各自開或關**（右鍵選單要顯示的功能）→ **標籤**：開＝打勾、關＝加號，可換行排列（4.4）。
  - **很多個**（語言、印表機、翻譯服務、解析度）→ 下拉選單。
  - 數字用欄位；開或關用勾選框。
- MD → PDF 因為範本卡片較高，紙張、文字大小、程式碼配色收在「進階選項」展開列，收合時在列上用**一句白話**寫出目前的設定（例如「A4 紙張，文字縮放 1 倍，程式碼區塊用深色底」）；「程式碼」要寫成「程式碼區塊」，避免被讀成整份文件是深色；檔案裡沒有程式碼區塊時省略這一項。
- 必選選項沒有預設值可用時一個都不選，開始按鈕停用並寫出要先選什麼。
- **Markdown 的 Word 範本**：點「選擇 Word 範本」卡片先開選檔視窗（.docx），取消就退回原本的範本。選好後這張卡片換成範本縮圖與檔名，卡片下方一行寫讀到的內容摘要（字型、字級、行距、邊界、標題置中），再下一行由左往右是「換一個範本」「設為預設值」。範本只決定字型、字級、行距、邊界與段落格式；紙張與程式碼配色不從範本讀取（紙張下方註明），進階選項的「文字縮放」直接寫倍率（0.9 倍／1 倍／1.12 倍，分段滑桿），表示在範本字級上整體放大或縮小；範本決定的字型、字級、行距、邊界等只寫在範本卡片下方。範本不能用（格式不對、損毀、太大）或設為預設值後找不到檔案時，同一列改成警示樣式並寫白話原因，開始按鈕停用並顯示「先換一個能用的範本」，不默默改用內建範本。
- 卡片上的值和功能預設值不同時，標籤右邊才出現「設為預設值」。
- 會影響隱私或結果的事直接寫在卡片上，不藏進進階選項。

### 4.10 命名規則

同一個功能在右鍵選單、動作頁標題、歷史紀錄的「動作」欄、完成通知都用**同一個功能名稱**；目錄卡片因為放進去的檔案類型已經確定，只用短名稱，說明句只在滑過時以提示顯示。功能名稱沿用 3.x 語系檔（`src/Clickra.Core/Resources/Locales/*.json` 的 `cmd_*`）已有的寫法：

- **處理類用「動作＋對象」**：合併 PDF、分割 PDF、壓縮 PDF、翻譯 PDF、列印 PDF、解密 PDF、壓縮圖片、合併圖片、拼接圖片、轉換圖片格式、批次重新命名。
- **轉檔類用「來源 → 目標」**（中間是箭頭）：Word → PDF、Excel → PDF、PPT → PDF、MD → PDF、PDF → 圖片、圖片 → PDF。動作頁同時處理多種 Office 檔時寫「Office → PDF」。
- **頁面分頁只用兩個字**：轉檔、歷史、設定。
- **成對的功能用成對的詞**：「解密 PDF」將來對應「加密 PDF」，不用「解除密碼／加上密碼」。
- **同一件事在設定頁與轉檔頁用同一組字**：設定頁「轉好的檔案存到」的選項是「原本的資料夾／桌面／下載／自訂…」，轉檔頁就寫「存到原本的資料夾」等。3.x 語系檔的舊說法（「預設輸出路徑」「與來源相同」）在 4.0 改掉，不沿用。
- **設定頁「功能預設值」以功能名稱分組**（壓縮 PDF、翻譯 PDF、PDF → 圖片、壓縮圖片、Office → PDF、MD → PDF）；組內每個選項的名稱與控制項種類，和該動作頁上完全相同（例如動作頁叫「壓縮程度」、用分段滑桿，設定頁也是）。右鍵選單的勾選清單、歷史紀錄也一律用功能名稱。

## 5. 內容超出畫面時的規則

### 5.1 通則

1. 工具列永遠固定，不隨內容捲動。
2. **捲動發生在深色區塊裡面，區塊本身不動**：每一頁的主要內容放在一個深色區塊中，區塊下緣固定在距視窗底部 24 的位置（與轉檔頁的動作區一致）；內容超出時在區塊內部捲動，捲動條位於區塊內側右緣。不採用「整頁內容連同區塊一起往上捲、捲到底才看到下緣留白」的做法。
3. 每一頁最多一個垂直捲動區；**不允許水平捲動**，也不允許捲動區裡再包捲動區（唯一例外：檔案清單，見下表）。
4. 主要按鈕（例如「開始」）與**正在進行的工作（進度）**必須始終看得到，不能被捲出畫面。
5. 捲動條使用 Avalonia Fluent 主題的預設樣式：平常是細條、滑鼠靠近才變寬、不佔版面寬度。捲動區右側預留約 10 的空間，避免細條壓在內容上。
6. 可以用滑鼠滾輪、觸控板、鍵盤（方向鍵、PageUp／PageDown）捲動。

### 5.2 各頁的捲動區

| 頁面／狀態 | 固定不動 | 會捲動的部分 | 何時會發生 |
| :--- | :--- | :--- | :--- |
| 轉檔 A（還沒放檔案） | 全部 | 無。高度不足時先減少「最近處理」的筆數（3 → 0），拖放區最小高度 240 | 視窗高度小於預設 |
| 轉檔 B（已放入檔案） | 檔案窄列；動作頁另固定標題列與最下方的存檔位置與「開始」 | 目錄：卡片區。動作頁：設定卡或工作區的指定區域 | 動作超過 8 個、設定卡展開進階選項、或介面語言文字較長 |
| 轉檔 C（管理檔案） | 窄列本身、最下方「再加入檔案」 | 清單列。清單最高展開到視窗高度的一半，超過就在清單內捲動 | 檔案超過約 4 個 |
| 歷史 | 標題與篩選列、進行中的工作、清單區塊的外框 | 清單區塊內的已完成紀錄 | 紀錄多於約 6 筆，或展開了詳情 |
| 設定 | 標題與「一般／功能預設值」切換鈕、設定區塊的外框 | 設定區塊內的內容 | 兩個分頁在預設大小下都會發生 |

### 5.3 過長的文字

- 檔名與路徑：單行顯示，放不下時結尾以「…」省略，滑鼠停留顯示完整內容。歷史詳情中的路徑允許換行。
- 按鈕與動作名稱：不省略。動作卡片的名稱最多兩行；其他語言（英、日、韓）文字較長時，以折行或增加列數處理，不縮小字級。

**按鈕與連結**

- 有底線的文字只用於**前往別的地方**：切到另一個分頁（例如「全部歷史」）或開啟網頁（例如 GitHub）。連到另一頁的某個區塊時（例如轉檔頁的「選擇右鍵選單要顯示的功能」），到達後要切到該區塊所在的分頁、捲到它，並以強調色淡底標示約 1.6 秒後淡出，讓使用者知道要看哪裡。
- 會**執行動作**的一律做成按鈕，不用底線文字：「變更」「換一個範本」「設為預設值」「指定位置」「處理其他檔案」等用有框的次要按鈕（高 32，畫面底部與主要按鈕並列時高 44）；「進階選項」這類展開收合用前面帶箭頭的展開列。
- 每個畫面只有一個強調色的主要按鈕。
- **文字本身就要看得懂**：不能靠顏色、粗細來區分名稱與值或表達狀態；拿掉顏色後意思仍須完整（顏色只做輔助，也照顧色弱與螢幕閱讀器使用者）。
- **按鈕一律保留文字**，常見動作在文字前加圖示（16，主要按鈕 18）：開啟所在資料夾／在資料夾中顯示用通用的資料夾圖示，再試一次用 ↻，開啟檔案用檔案圖示。不用檔案總管、Finder 等各平台檔案管理員的圖示。只有兩種情況可以只放圖示：同一個清單每一列都重複出現同樣按鈕時；以及設定頁「關於」那一列少用的連結與工具（GitHub 專案頁、檢視日誌、寄送問題回報）。只放圖示時一律在滑過時顯示名稱，並提供給螢幕閱讀器的名稱；不使用 GitHub 等品牌標誌，改用通用圖示。所有線條圖示都畫在同一個 24 × 24 格子上、整體等比縮放（同樣的線條粗細與基準線），不可把單一圖示各自拉伸到填滿，否則大小與粗細會不一致。
- **「…」只用在選單與下拉選單的文字項目**，表示點了會先跳出視窗要你再選（例如下拉選單裡的「選擇 Word 範本…」「自訂…」）。卡片、按鈕本身的外觀已經看得出會開視窗（例如虛線框加號卡片），就不加「…」。

## 9. 尚未定案事項

0. 加密 PDF 經「解鎖後再處理」所產生的輸出檔是否仍帶密碼。目前專案只有「解密 PDF」、沒有「加密 PDF」，若輸出檔會變成沒有密碼，必須在密碼欄位旁明確告知使用者。
1. Linux 上工具列能否延伸進標題列（3.1），需以實機驗證。
2. 處理中是否保留 3.x 的「縮小到系統匣」。
3. 圖片「合併」與「拼接長圖」的差異是否需要在動作名稱上講得更清楚；Markdown 進階選項（紙張、文字大小、程式碼配色）的排列。
4. 淺色主題色票（7.1）為草案，狀態色與強調色在白底上的對比待確認。
5. 強調色是否改回 3.x 使用的紫色。
6. macOS 與 Linux 是否採用各自平台的視覺慣例，或三個平台共用同一套外觀。
7. 右鍵選單的顯示開關能否即時生效（Windows 11 新式選單預期可以；Windows 10 傳統選單可能需要重新註冊），以及 Windows 11 新式選單是否支援「Clickra ▸ 轉換格式 ▸ 格式」這樣的第二層子選單。
8. **動作圖示的辨識度**：現有功能圖示主色（#475569）在深色卡片上對比約 2:1，且合併、PDF → 圖片、翻譯、重新命名都是「疊卡片」造型，使用者會先讀文字。第一步（版面）：目錄圖示放大並墊亮底，三種做法並排在畫布「比較：動作目錄的圖示大小」待選。第二步（圖示本身）：每個功能改用形狀明顯不同的主符號、深色主題提高亮度，並考慮滑過卡片時播放小動畫說明功能（例如分割：一張紙中間出現剪刀剪成兩張；系統開啟「減少動態效果」時不播放）。圖示與檔案總管右鍵選單共用。
