# Clickra 介面文字寫法

> 狀態：使用中（2026-11-20 起）
> 適用：4.0 桌面版（`Clickra.Desktop`）所有畫面上的文字，以及它們在五種語言的翻譯。新增或修改任何介面文字前先看這份。
> 來源：2026-11-20 逐條審過 410 條介面文字時和使用者一起定下的規則；對照表見「Clickra 4.0 介面文字對照表」。
> 相關：功能名稱見 [v4_desktop_ui_layout.md](v4_desktop_ui_layout.md) 4.10；翻譯流程見 [v4_localization_plan.md](v4_localization_plan.md)。

## 1. 寫什麼、不寫什麼

1. **只寫使用者要知道或要做的事。** 程式在背後替使用者做的事不用說明。
   例：處理好幾個有密碼的檔案時，後面的檔案會自動先試同一組密碼——不寫；「另存一份新檔」是每個動作的共同做法——不寫。
2. **不猜原因。** 找不到檔案就寫「找不到「報告.pdf」」，不加「可能已被移動或刪除」；範本打不開就寫「無法使用「報告範本.docx」這個範本」，不加「格式不對或檔案損毀」。
   例外：原因不明顯、而且使用者能據此處理時才寫，例如「找不到 E:，可能是隨身碟或網路磁碟沒有接上」。
3. **說出結果，不只說理由。** 「沒有密碼或使用限制，已略過」，而不是「不用解密」。
4. **能短就短。** 同一句裡意思重複的部分只留一個（「只用這一次」與「不會儲存」只留後者）；視窗標題不重複開啟它的那個設定名稱（「選擇儲存資料夾」，不寫「選擇轉好的檔案要存到哪裡」）。
5. **不用稱呼。** 不寫「你」「您」；「沒有你要的？」寫成「找不到想要的功能？」。
6. **不像程式在說話。** 不寫「讀到：」「操作」「執行中」這類系統用語；寫「範本格式：」「處理中」。

## 2. 用詞

同一件事整個介面只用一個詞。下表是已定的說法，左邊是要用的、右邊是不要用的。

| 用 | 不用 | 說明 |
| :--- | :--- | :--- |
| 處理、處理中、處理完成、再處理一次 | 轉換、轉檔中、執行、再轉一次 | 動作一律說「處理」；「轉成」只用在真的換格式的動作名稱（轉成 PDF、轉成圖片） |
| 轉檔（分頁名）、到轉檔頁 | 去轉檔 | 分頁名稱固定兩個字（4.10） |
| 轉好的檔案、原本的檔案 | 輸出、輸入、來源 | 與設定頁「轉好的檔案存到」一致 |
| 原本的資料夾、開啟原本的資料夾 | 來源資料夾、與來源相同 | |
| 停止、已停止 | 取消操作、已取消 | 按鈕叫「停止」，狀態就是「已停止」；「取消」只用在對話框的取消按鈕和取消切點 |
| 已暫停 | 暫停中 | |
| 完成、沒有完成 | 成功、失敗、未完成 | 結果頁與歷史頁的篩選都用這組 |
| 略過、會略過、已略過 | 不用處理 | |
| 使用限制 | 限制、權限 | 「有密碼或使用限制」 |
| 開啟 | 打開 | |
| 選擇（按鈕、視窗標題）、選（短句裡） | | 「選擇檔案」「選擇 Word 範本」；「先選印表機」 |
| 點、點兩下 | 按、按一下、雙擊 | 滑鼠動作；「按右鍵」是慣用說法，保留 |
| 紀錄（歷史頁的每一筆） | | 所以記錄檔叫「日誌」，不叫「紀錄檔」 |
| 不變 | 保持原樣 | 重新命名的大小寫、副檔名選項 |
| 依印表機設定 | 印表機預設 | 避免和「系統預設印表機」混淆 |
| 還不能處理 | 還沒有處理…的功能 | 「Clickra 還不能處理影片」 |

功能名稱、目錄卡片名稱與說明句見 4.10，這裡不重複。

## 3. 格式

1. **檔名、資料夾名加「」**：「「報告.pdf」有密碼，請輸入」「找不到「輸出」資料夾」。不寫完整路徑，除非使用者要靠路徑判斷（設定頁顯示的儲存位置）。
2. **清單用「、」**，太長時寫「報告.pdf、附錄.pdf 等」。
3. **句號**：只有一句的提示、按鈕、標籤不加句號；兩句以上的說明才用句號分句，最後一句也加。
4. **數字和中文之間空一格**：「3 個檔案」「第 2 份」「12 pt」。英文、副檔名與中文之間也空一格：「Clickra 還不能處理」「把 Markdown 轉成 PDF」。
5. **全形標點**：，。；：？（）「」；省略號用「…」（一個字元），不用「...」。箭頭用「→」，前後各空一格。
6. **時間**：只到分（「今天 14:02」）；花了多久：不到 1 秒寫「不到 1 秒」，1 分鐘內寫整數秒「3 秒」，超過寫「2 分 15 秒」。
7. **計數單位**：檔案用「個」，圖片用「張」，PDF 的份用「份」，頁用「頁」。

## 4. 存進語系檔的方式

1. **一句完整的話＝一個鍵。** 不把一句拆成幾段再拼；有幾種情況（一個檔案／多個檔案／部分檔案）就寫幾個完整的鍵。
2. **變數用名字**：`{count}`、`{name}`、`{types}`，不用 `{0}`、`{1}`，翻譯時才知道每個變數是什麼、也能搬到句子任何位置。
3. **只有數量不固定的清單由程式組**，分隔符號放在 `ui_list_separator`（中文「、」、英文「, 」），也跟著語言走。
4. **換行寫在同一個鍵裡**（`\n`），例如「建議新功能」的整封信是一個鍵。
5. **在程式裡取字**：`Strings.T("ui_…")`、`Strings.F("ui_…", ("name", 檔名))`、有數量用 `Strings.Count("ui_…", n)`（英文 `_one` 自動處理單數）、清單用 `Strings.List`／`ShortList`；XAML 寫 `Text="{l:T ui_…}"`。
6. **提示列**（動作清單上方那種「原因＋影響＋按鈕」的說明）共用同一個元件；文字仍是完整句子，按鈕文字另一個鍵。

## 5. 檢查

架構測試（見 v4_localization_plan.md 第 5 節第 7 項）另外檢查：

- `ui_*` 的值不以標點開頭、不以「，」「、」或半個括號結尾（抓出被拆開的句子）。
- 繁中值裡不出現第 2 節表格右欄的詞、不出現「你」「您」、不出現「...」。

新增文字時，先在這份文件的用詞表找有沒有現成的說法；沒有、而且會在兩個以上的地方用到，就把新詞加進表裡。
